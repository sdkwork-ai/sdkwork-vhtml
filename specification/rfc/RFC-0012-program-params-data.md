# RFC-0012：程序参数与外部数据块

- 状态：已采纳（VHTML 1.1 代码创作扩展）

## 背景

创作程序在 1.1.1 已能从内联 JSON 数据块取数，但两类真实工作流缺失：

1. **参数化模板**：同一文档批量产出不同成片（换文案、换色、换数量），
   需要把外部参数安全地传入沙箱；规范曾声明 `--param` 能力但 CLI 未接线。
2. **外部数据**：数据驱动的字幕、账目、图表数据通常独立于文档维护，
   内联 JSON 让大文件挤占 `.vhtml` 主体、难以复用与打包。

## 决策

1. `--param k=v` 为可重复 flag（`k=v=v` 保留首个 `=` 之后全部），
   经 `materializeDocument({ params })` 合并进 `vhtml.ctx.params`，
   外部值覆盖文档 `params` 属性；CLI 进程级共享，全部加载路径生效。
2. `<data src="…">` 外部数据块：项目根相对路径，沿用外部 Scene 的路径
   沙箱（URL 拒绝、根转义/链接逃逸拒绝），`src` 优先于内联内容，
   序列化保留引用形式以便往返与审阅；文件位于 `assets/` 即随
   `.vhtmlpkg` 打包。
3. 参数与数据都是**构建期**输入：不进入渲染期，不破坏确定性契约
   （相同文档 + 相同参数 + 相同数据 = 相同模型）。

## 备选方案

- 在沙箱内开放 `fetch`/fs 读取数据：破坏确定性沙箱边界，否决。
- 数据引用（`ref:`）形式的资源系统：与 Asset 语义重叠且需要在
  物化后再解析，v1 以 `<data src>` 的解析期读取更直接。

## 结果

- 模板化批量生产：`--param` 一次声明，CI/智能体按参数矩阵出片。
- 大数据文件外置，`.vhtml` 保持可读；打包/分发路径不变。

## 测试

- `tests/unit/program-data.test.ts`：外部数据读取/往返、URL 与根转义
  拒绝、参数合并优先级、conformance 参数夹具。
- CLI 冒烟：`--param` 三种形式（空格、`=`、重复）强验证（参数缺失即
  报错的程序文档）。
